# zxxk-zujuan-paper-downloader

> 学科网 / 组卷网个人题库离线导出工具。  
> 一个基于 **Tampermonkey（篡改猴）** 的单文件用户脚本，用于把当前页面中的题目、答案、解析与图片资源整理成可离线保存、打印、归档的 HTML / ZIP。

当前推荐版本：**v3.1 维护版（以 v2.2 为唯一主线）**
当前主脚本：`scripts/zxxk-zujuan-export.user.js`

v3.1 不替换 v2.2 的界面、设置布局或导出习惯；它只补充 v2.2 在真实页面中暴露的功能性稳定性问题。

## 项目定位

本项目最初只是一个“纯净打印”脚本：清理学科网 / 组卷网页面中的广告、导航、知识点、来源等干扰元素，修复浏览器打印时的空白页和版式错乱。

后来它逐步演进为一个更完整的 **个人题库离线导出工具**：

- 不做独立爬虫；
- 不跑后台服务；
- 不批量扫描站点；
- 只在你当前打开的组卷网页面内工作；
- 通过 Tampermonkey 用户脚本读取当前页面已经呈现或引用的题目、答案、解析、图片资源；
- 输出 HTML 或 ZIP，方便离线查看、打印、归档。

---

## 当前能力

v2.2 主线及其 v3.1 维护层重点解决四个问题：

1. **题目离线保存**
   - 将个人题库页面中的题目导出为单个离线 HTML；
   - 或导出为 ZIP，每题一个 HTML 文件。

2. **答案 / 解析合集导出**
   - 优先自动展开“显示全部答案和解析”；
   - 即使页面没有全局开关，也会滚动并逐题点击答案区域，等待 AJAX 答案节点或图片真正插入；
   - 恢复答案图片的 `data-src` / `data-original` 懒加载属性后再导出；
   - 收集每道题的答案块、解析图片和关联题干；
   - 支持导出单个答案合集 HTML；
   - 支持导出答案 ZIP。

3. **图片与公式资源处理**
   - 支持将图片 / 公式转为 Data URI 嵌入 HTML；
   - 支持把图片作为独立文件写入 ZIP；
   - 处理 `img[src]`、懒加载属性、`srcset`、inline `style=url(...)`、computed `background-image`；
   - v2.2 增加 `GM_xmlhttpRequest` 回退，解决部分答案图片接口在浏览器 `fetch()` 下 `Failed to fetch` 的问题。

4. **可控的稳定性保障（v3.1）**
   - 正式进度、取消当前导出、请求超时与重试；
   - 仅在本地生成的页面兼容性检查和诊断 JSON；
   - 诊断记录逐题预加载结果、选择器统计和资源失败信息，不会上传页面内容。

## 安装方法

### 1. 安装 Tampermonkey

先在浏览器安装 Tampermonkey（篡改猴）或兼容的用户脚本管理器。

### 2. 安装脚本

打开：

```text
scripts/zxxk-zujuan-export.user.js
```

复制全文，在 Tampermonkey 中：

```text
管理面板 → 添加新脚本 → 粘贴 → 保存
```

### 3. 刷新组卷网页面

访问：

```text
https://zujuan.xkw.com/
https://www.zxxk.com/zujuan/
```

进入个人题库、组卷结果页或包含题目列表的页面后，等待右侧导出面板出现。

## 使用方法

脚本加载后，会在页面右侧生成一个固定面板：

```text
离线导出 & 答案合集
```

主要按钮如下。

### 生成题目离线 HTML

适合：

- 想把当前页面题目合并成一个文件；
- 想直接浏览器打开；
- 想打印为 PDF；
- 想保留图片 / 公式。

输出示例：

```text
personal_tk_offline_2026-06-21_05_47_05.html
```

### 生成题目 ZIP

适合：

- 想每道题独立一个 HTML；
- 想批量归档；
- 想按 QID 检索。

ZIP 内部示例：

```text
personal_questions/
├─ QID_34015307_idx1.html
├─ QID_34015309_idx2.html
└─ ...
```

### 导出答案合集 HTML

适合：

- 想把所有答案和解析汇总成一个 HTML；
- 想直接打印或发给自己归档；
- 想开启“嵌入答案图片为 Data-URI”，做成单文件离线版。

输出示例：

```text
answers_collection_2026-06-21_05_47_05.html
```

### 导出答案 ZIP（图片 / HTML）

适合：

- 想每题一个答案 HTML；
- 想把答案图片独立保存到 `answers_images/`；
- 想同时获得 HTML 版答案和原始图片文件。

> 说明：答案 ZIP 会始终写入 `answers_images/`。如果勾选“嵌入答案图片为 Data-URI”，每题 HTML 中也会再内嵌一份图片，方便单个 HTML 离线查看，但 ZIP 体积会更大。

ZIP 内部示例：

```text
answers_html/
├─ QID_34015307.html
├─ QID_34015309.html
└─ ...

answers_images/
├─ QID_34015307_ans1.png
├─ QID_34015309_ans1.png
└─ ...
```

## 面板参数说明

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 并发 | `3` | 同时处理资源的数量。过高可能触发站点限制。 |
| 延迟(ms) | `120` | 每次资源请求前的基础等待时间。 |
| 重试 | `2` | 资源请求失败后的重试次数。 |
| 超时(ms) | `25000` | 单个资源请求最长等待时间。 |
| 封禁 ms | `600000` | 遇到 403 / 429 后的保护等待时间，默认 10 分钟。 |
| 最大嵌入总 MB | `8` | Data URI 嵌入模式下的总大小阈值。 |
| 去重(QID) | 开启 | 按题目 QID 去重，避免重复导出。 |
| 嵌入答案图片为 Data-URI | 开启 | 仅影响 HTML 内是否嵌入图片；答案 ZIP 始终会在 `answers_images/` 保存图片文件。 |
| 导出时按 QID 去重 | 开启 | 答案导出时按 QID 合并重复题。 |
| 单题等待(ms) | `2500` | 点击单题答案区域后，等待异步答案插入页面的时间。 |
| 点击次数 | `1` | 单题未出现答案时的最多重试点击次数，范围 1–3。 |

建议：

- 如果导出速度过慢，可以适当提高并发；
- 如果出现 403 / 429，应降低并发、增加延迟；
- 如果 HTML 文件太大，关闭 Data URI 嵌入，改用 ZIP 保存图片文件。
- 若答案需要点击后才出现，保持默认“单题等待 2500ms”；慢页面可先提高到 5000ms，再把“点击次数”调为 2。

## 导出结果说明

### HTML 模式

HTML 模式优点：

- 文件直观；
- 双击即可打开；
- 适合打印 / 打印为 PDF；
- 开启 Data URI 后可以成为真正单文件离线版。

缺点：

- 图片转 Base64 后体积会变大；
- 大量题目时浏览器打开可能较慢。

### ZIP 模式

ZIP 模式优点：

- 适合大量题目；
- 每题独立 HTML；
- 图片可独立保存；
- 更适合归档和后续处理。

v2.1 起，ZIP 不再依赖外部 JSZip CDN，而是内置最小 ZIP 写入器，因此：

- 不需要加载 `cdn.jsdelivr.net`；
- 不受 JSZip 加载失败影响；
- ZIP 下载更稳定；
- 生成的是 STORE/no compression ZIP，即不压缩，只打包。

v2.1 解决 ZIP 生成与下载问题：

- 移除运行时 JSZip 依赖；
- 不再依赖 `cdn.jsdelivr.net`；
- 内置最小 ZIP 写入器；
- 使用 STORE/no compression 打包；
- 改进 Blob 下载逻辑；
- 增加手动下载链接；
- 修正答案 ZIP 中 `answers_html/*.html` 引用 `answers_images/` 的相对路径。

这一版让“能不能生成 ZIP”从外部依赖问题变成脚本内能力。

### v2.2：答案图片跨域回退主线

主线快照：

```text
scripts/zxxk-zujuan-export.user.js
```

v2.2 解决答案图片 `Failed to fetch` 问题：

- 增加 `GM_xmlhttpRequest` 权限；
- 增加 `@connect imzujuan.xkw.com` 等连接声明；
- 对 `imzujuan.xkw.com/getAnswerAndParse/...` 答案图片接口使用油猴跨域请求回退；
- 普通题目资源仍优先走浏览器 `fetch()`；
- 答案合集 HTML 与答案 ZIP 共用同一个资源获取逻辑；
- 经用户实测，方案可行。

这一版的定位是：**单脚本、无爬虫、可离线导出题目与答案的主线**。v3.1 不改变这个定位，也不替换其界面风格或设置布局。

### v3.1：v2.2 主线的答案懒加载维护版

v3.1 专门处理一类实际页面：没有“显示全部答案和解析”全局开关，答案必须逐题点击后才通过 AJAX 插入 DOM。导出前执行顺序为：

1. 尝试现有全局开关（存在时）；
2. 滚动当前题；
3. 点击 `.exam-item__cnt`，其次 `.wrapper.quesdiv`，再退回题目节点；
4. 通过 `MutationObserver` 与轮询等待文本、结构化内容或非占位图片出现；
5. 将 `data-src` / `data-original` 恢复为可导出的 `src`；
6. 再复用 v2.2 的跨域图片回退、HTML/ZIP 与内置 ZIP 写入器。

同时加入：

- 进度、取消、请求超时和任务级资源缓存；
- 每题预加载结果、资源失败和选择器统计的本地诊断 JSON；
- 相对路径答案图片在单文件 HTML 中的可靠 Data URI 重写；
- 无外部 `@require` 依赖的回归检查与懒加载页面夹具。

这是功能维护版本，**不是 3.0 UI 的回归或迁移**。

仓库历史中曾出现一个 `3.0.0-alpha.4` 元数据版本的黑金测试版。它更适合被看作“特别测试服”或“实验分支”，而不是 v2.2 之后的常规升级路线。

## 常见问题

### 1. 为什么我看到“Failed to fetch”？

如果是普通图片，可能是网络、CORS 或资源失效。  
如果是答案图片，v2.2 主线已加入 `GM_xmlhttpRequest` 回退，请确认安装的是 v3.1（或 v2.2），并且 Tampermonkey 已授予跨域请求权限。

### 2. 为什么 ZIP 不压缩？

v2.1 起内置的是最小 ZIP 写入器，使用 STORE 模式，只负责打包，不做压缩。

这样做的原因：

- 避免依赖 JSZip；
- 避免 CDN 加载失败；
- 降低脚本复杂度；
- 提升生成成功率。

### 3. 为什么 HTML 文件很大？

开启 Data URI 嵌入后，图片会变成 Base64 字符串写进 HTML，体积通常会明显变大。

解决方法：

- 降低导出题量；
- 调低“最大嵌入总 MB”；
- 关闭“嵌入答案图片为 Data-URI”；
- 改用 ZIP 模式保存图片文件。

### 4. 为什么导出时页面很慢？

资源下载、图片转 Base64、ZIP 打包都会占用浏览器内存和 CPU。

建议：

- 每次导出少量题；
- 并发不要过高；
- 大题量优先用 ZIP；
- 避免多个导出任务同时运行。

### 5. 为什么导出的答案全是“未抓到答案内容”？

这是 v3.1 重点修复的问题。某些页面没有全局“显示全部答案”按钮，单题答案需要点击后才会异步插入页面；此前若只检查页面初始 DOM，就会误判为空。

v3.1 会按“全局开关（若有）→ 滚动 → 逐题点击 → 等待 DOM 变化 → 恢复懒加载图片”的顺序预加载。导出日志会显示“已有 / 点击加载 / 未加载”的计数。

如果仍有少数题未加载：

- 先将“单题等待(ms)”调到 `5000`；
- 再把“点击次数”调为 `2`；
- 点击“检查页面兼容性”，并下载“本次诊断 JSON”；
- 将不含题目正文的诊断结果和页面结构变化反馈到项目 Issue。

### 6. 为什么有些题仍没有答案？

可能原因：

- 页面本身没有展开答案；
- 页面结构改版；
- 答案图片接口权限不足；
- 该题答案需要额外交互后才加载。

可以先在页面手动点击“显示全部答案和解析”，再运行导出；若页面没有这个开关，v3.1 会自动尝试逐题点击。脚本不会绕过站点权限，也不会虚构不存在的答案内容。

## 开发说明

当前主脚本是一个单文件 Tampermonkey 用户脚本，核心模块包括：

- 页面面板构建；
- 题目节点收集；
- 答案节点收集；
- 资源 URL 归一化；
- `fetch()` + `GM_xmlhttpRequest` 资源获取；
- Blob → Data URI；
- 内置 ZIP 写入器；
- HTML / ZIP 下载触发。

如果后续继续开发，建议保持以下原则：

1. 主线仍保持单脚本；
2. 不引入后台服务；
3. 不引入爬虫式批量任务；
4. 优先修复当前页面导出稳定性；
5. 历史脚本版本放入 `scripts/versions/`，历史文档放入 `docs/archive/`，不要混在根目录。
6. v2.2 是界面与交互主线；功能维护必须优先保持其按钮、设置和导出结果兼容。
